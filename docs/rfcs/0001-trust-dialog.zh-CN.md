# RFC 0001 — 项目信任对话框

- **状态**：草案
- **目标版本**：v0.2.0
- **作者**：Mindora 维护者
- **讨论**：https://github.com/Reamory/Mindora/discussions

## 概要

当用户第一次在 Mindora 中选择工作目录（或在被"Do not trust"拒绝之后再次选择），应用必须弹出一个对话框，说明智能体在该文件夹中将能做什么，并请用户选择一个信任等级。这个选择会持久化到磁盘，且可在 设置 → 安全 中随时修改。

## 动机

今天，在 Mindora 里选一个项目就等于默默授予智能体完全访问权。没有确认、没有日志、没办法撤销。上游的 `pi-coding-agent` 已经自带一个 `trust-manager.js`，支持按文件夹信任决策，但 Mindora 并没有调用它。本 RFC 提出把这个能力接进来。

## 设计

### 触发时机

以下任一情况发生时弹出对话框：

1. 用户在侧边栏选了一个新项目（`cwd` 与上一个不同）。
2. 用户在"需要信任"警告横幅上点了"信任此文件夹"。
3. 用户进入 设置 → 安全，点击"重新评估信任"。

### 对话框内容

```
┌──────────────────────────────────────────────────────────┐
│ Mindora 想在这个文件夹工作                                │
│                                                            │
│ C:\Users\chiqu\Desktop                                     │
│                                                            │
│ Mindora 将允许智能体：                                     │
│   • 读取此文件夹中的任何文件                                │
│   • 运行 shell 命令（bash、git、npm 等）                   │
│   • 编辑和写入此文件夹中的文件                              │
│   • 调用任何已安装的 skills / 插件                          │
│                                                            │
│ 智能体不会：                                               │
│   • 把你的文件发送到任何服务器（无遥测）                    │
│   • 触碰此文件夹之外的目录（除非你同意）                    │
│   • 在没有审批弹窗的情况下自动运行任何东西                  │
│                                                            │
│ ┌────────────────────────────────────────────────────┐   │
│ │ 信任此文件夹                                         │   │
│ │ 信任父文件夹 (C:\Users\chiqu)                        │   │
│ │ 信任此文件夹（仅本会话）                             │   │
│ │ 不信任                                               │   │
│ └────────────────────────────────────────────────────┘   │
│                                                            │
│                          [取消]   [继续]                    │
└──────────────────────────────────────────────────────────┘
```

四个选项对应上游 `getProjectTrustOptions()` API 和 `getProjectTrustParentPath()` 助手。只有当存在父目录时才显示"信任父文件夹"。

### 持久化

对话框的选择通过智能体的 `setProjectTrust()` API 传给上游。智能体把一个 `trust.json` 写在 `~/.pi/agent/` 旁边。Mindora 不需要自己的存储 —— 单一真相之源。

### 在 UI 中的位置

对话框是一个模态浮层（半透明背景，居中卡片）。它**不能按 ESC 关闭**，除非用户点取消 —— 在信任决定之前，智能体无法运行。

如果用户点取消，Mindora 把项目选择器回滚到上一个文件夹。

### 边界情况

- **沙箱化 IDE**（TRAE、VS Code Dev Containers）：对话框仍然显示，但显示的是沙箱内路径（如 `/workspace`），而不是宿主机路径。
- **网络驱动器**：带黄色警告显示，但信任仍然有效。
- **符号链接**：信任适用于规范化路径，不是符号链接本身。
- **用户拒绝后再次选同一文件夹**：对话框再次出现（不缓存"拒绝"）。

### 不在范围

- 按工具的权限切换（由 RFC 0002 处理）。
- 仅本会话的信任：延后到 v0.7.0。

## 实现

### 新增文件

- `app/api/trust/route.ts` —— GET/POST 信任决策。
- `components/TrustDialog.tsx` —— 模态框。
- `hooks/useProjectTrust.ts` —— 获取并持久化信任。

### 修改文件

- `components/SessionSidebar.tsx` —— `selectedCwd` 变化时触发对话框。
- `app/api/agent/...` —— 在允许任何工具执行前调用 `setProjectTrust()`。
- `lib/i18n/dictionary.ts` —— 为 3 种语言添加 `trust.*` 键。

### 调用顺序

```
用户选择新文件夹
  → 侧边栏调用 useProjectTrust.fetch(cwd)
  → 如果没有决策，打开 TrustDialog
  → 用户做出选择后，POST 到 /api/trust
  → 服务端调用 agent.setProjectTrust(cwd, decision)
  → 侧边栏用新状态重新渲染
  → 允许发送第一条消息
```

## 待回答问题

1. "不信任"应该阻止消息发送，还是只阻止工具执行？**建议：阻止工具执行；消息发送保持开放，以便用户阅读历史会话。**
2. 我们要不要在侧边栏用一个状态图标展示信任状态？**建议：要 —— 已信任显示绿色对勾，已拒绝显示红点，未决显示灰问号。**

## 备选方案

- **静默信任 + 仅审计日志。** 拒绝。审计日志是事后追查，用户必须一开始就同意。
- **仅首次运行时。** 拒绝。用户经常切项目，每次切换都需要自己的同意。
- **操作系统级权限弹窗**（macOS Accessibility、Windows UAC）。拒绝。对开发工具来说太重了。

## 上线计划

- v0.2.0-alpha.1：对话框在特性开关后发布（`MINDORA_TRUST_DIALOG=true`）。
- v0.2.0-alpha.2：默认启用对话框；测试 trust.json 迁移。
